# jieyatai-1 发布说明

技术版本：1.0.0

## 本次实现

- 发布版本名改为 `jieyatai-1`；Tauri、Cargo 与 npm 使用兼容构建工具的语义版本 `1.0.0`。
- 修正“源码包直接打开像是无法访问页面”的体验：`index.html` 在 `file://` 打开时会明确说明原因，并新增 `start-web-preview.cmd` 和 `start-tauri-dev.cmd`。
- Vite 增加相对资源基路径，并新增 `npm run preview:browser`，统一使用 `127.0.0.1:5173` 打开浏览器预览。
- 总设置新增“显示详细解释”，用于按需显示更长的用途、影响范围与注意事项。
- 总设置新增独立“通道解压地址”页，可集中管理所有通道地址。
- 通道地址页支持跟随压缩包/指定目录、手输路径、目录选择、默认地址、最近地址、首个文件目录、搜索以及空地址补全。
- 设置搜索加入“通道解压地址”和“显示详细解释”，支持 `jydz`、`tdml`、`dz`、`xxjs` 等缩写。

## 关于“无法访问页面”

上一版 ZIP 是 Vite/Tauri 源码工程。项目根目录的 `index.html` 依赖 Vite 对 `/src/main.ts` 的编译和模块服务，因此不能把源码 `index.html` 当作已经构建好的静态网页直接双击运行。如果访问 `localhost:5173` 时 Vite 未启动，浏览器也会显示无法访问。

本版在 Windows 下可直接双击 `start-web-preview.cmd`。首次运行会尝试安装依赖，然后启动 Vite 并打开浏览器。完整桌面功能使用 `start-tauri-dev.cmd`。

## UX2 增量优化

- 工作区显示项统一使用“开关”命名，并新增 8 个可见性开关。
- 空队列点击开始默认扫描关键词收件目录中的最新版并自动开始。
- 通道卡片可直接删除已保存预设，带确认与反馈。
- 设置搜索支持 `kg=开关`，保留 `qd=启动`。
- 开始流程拆分为 `channelStartActions.ts`，降低主通道 store 的职责密度。
