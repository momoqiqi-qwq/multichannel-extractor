# 解压台 0.7.0 UX 与可靠性优化报告

## 优化目标

本轮围绕用户在批量解压中的五个核心焦虑展开：

1. 应用意外退出后是否要重新配置所有任务；
2. 点击开始前是否知道输出到哪里、会不会覆盖、空间够不够；
3. 任务开始后是否能暂停、调顺序、判断还要多久；
4. 设置是否容易找到、是否有足够自由度；
5. 新功能是否有清晰的验收边界。

## 关键设计决策

### 任务恢复只持久化安全快照

任务历史保存源路径、目标路径、层级、冲突策略等恢复必需字段，但主动移除密码，只保留 `requiresPassword` 布尔标记。这避免了“恢复方便”以牺牲密码安全为代价。

恢复任务默认高优先级，避免用户点击恢复后仍被大量普通任务压后。对于找不到源文件或格式不再支持的任务，恢复流程立即给出错误，不生成无效队列。

### 开始动作改为“检查—预览—确认”

原先“开始”是一次不可见的直接提交。0.7.0 增加开始前确认层：

- 先在 Rust 端计算最终目标路径并检查本地环境；
- 再在界面聚合错误、警告和提示；
- 最后由用户确认提交。

阻止项和警告项使用不同语义。错误会禁用确认按钮，警告只提示风险，避免把所有提示都变成无法继续的强制流程。

### 暂停采用协作式检查点

直接冻结线程或子进程可能导致文件句柄、临时文件和目标目录锁处于不可控状态。因此内置解压器采用 `TaskControl::checkpoint()`：在安全的读取、写入和整理边界等待继续。排队阶段也会观察暂停状态，不进入实际解压。

外部 RAR/7Z 工具无法保证中途冻结后仍安全恢复，因此文档和界面只承诺调用边界响应。

### 优先级与现有队列策略组合

优先级不是替换原“按通道/轮询”策略，而是增加一层稳定排序：

1. 按高、普通、低分为三个全局层级；
2. 每个层级内部继续使用用户选择的通道顺序或轮询。

这样既能保证紧急文件先处理，又不会破坏用户对通道公平性的预期。

### 设置页从功能堆叠转向信息架构

设置页采用九个可搜索分类：常规、界面与字体、操作与导航、输出默认值、可靠性、自检与恢复、项目工具、模板与维护、说明与版本。

常用入口集中在“常规”，低频高风险选项保留在对应专业分类。紧凑侧栏让小窗口仍保留足够内容宽度。

## 用户体验优化清单

- 版本号在设置标题、侧栏底部和关于页一致显示。
- 新增安全、均衡、极速、极简设置方案，降低初次配置成本。
- 新增恢复横幅，只有存在中断任务时出现。
- 预检查页显示任务数、警告数、阻止项和检查信息总数。
- 输出路径以源→目标与树状分支同时表达。
- 文件、通道和任务中心的暂停状态与操作一致。
- ETA 只在排队或处理中显示，暂停期间隐藏并停止计时。
- 模板导入导出独立于完整配置，避免误覆盖工作区。
- 背景焦点支持拖动、滑杆和一键居中三种操作方式。
- 设置、任务中心和日志抽屉互斥；Esc 统一关闭临时层。
- 浏览器预览无法访问本地能力时显示降级提示，而不是伪装成完整检查。

## 技术优化

- 配置结构升级为 v7，保留 v1–v6 迁移路径。
- 任务历史升级为 v2，兼容 v1 记录。
- 新增 `TaskControl`，取消和暂停共享统一控制对象。
- 新增 `fs2` 磁盘可用空间检测。
- 队列构建器独立处理优先级层级。
- 通道模板操作复用现有规范化逻辑。
- 版本信息集中到 `src/config/version.ts`，避免界面硬编码。
- 静态检查脚本覆盖 0.7.0 的核心文件、命令注册、默认设置和文档。

## 风险与限制

- 精确解压后大小需要读取归档元数据；当前倍率估算更稳健但不精确。
- 密码正确性无法跨 ZIP、7Z、RAR 用统一轻量方式验证。
- 对外部子进程进行强制暂停会增加数据损坏风险，因此未采用。
- 任务级重跑可能再次处理已写入部分；冲突策略和安全删除清单用于降低影响，但不等同于事务回滚。
- 未在当前交付环境完成真实 Tauri 构建，必须在具备 Rust 和 npm 依赖的机器上执行完整检查。
