# 开发过程记录

本文件记录本项目每次开发或迭代应执行的必要过程，避免只修改界面而遗漏后端、安全、跨平台和验证工作。

## 1. 需求基线

每次开始迭代前确认以下范围：

- 通道数据是否仍保持完全隔离。
- 新功能是通道级、文件级还是全局级。
- 是否改变目标路径、输出容器、目录深度或文件冲突语义。
- 是否新增压缩格式、系统依赖、权限或 Tauri capability。
- 是否需要迁移 `localStorage` 中的通道配置或预设。

## 2. 数据模型先行

1. 在 `src/types.ts` 更新前端类型。
2. 在 `src-tauri/src/models.rs` 更新 Rust 结构体和 `serde` 命名。
3. 确认 camelCase 字段在两端完全一致。
4. 对枚举使用显式 tag，例如：

```json
{ "type": "flatten", "depth": 2 }
```

## 3. 后端实现顺序

1. 格式识别和输入校验。
2. 解压到临时目录，禁止直接把归档条目写入最终目录。
3. 验证路径组件，拒绝绝对路径、父目录跳转、设备节点和符号链接。
4. 先确定输出容器，再应用归档内部目录深度映射。
5. 明确验证“直接写入”和“压缩包同名文件夹”两种容器。
6. 使用可预测的策略解决重名。
7. 在耗时循环中检查取消标志。
8. 发出进度、完成和批次结束事件。
9. 为路径映射与真实落地目录补充单元测试。

## 4. 前端实现顺序

1. Pinia action 负责业务状态，不在组件中直接拼装 Rust 请求。
2. 组件只处理输入、展示和用户事件。
3. Tauri listener 必须在组件卸载时调用 `unlisten`。
4. 拖放事件按窗口缩放因子换算坐标，再确定目标通道。
5. 所有失败路径都应落入文件状态和日志，不只写 `console.error`。
6. 操作按钮根据目标路径、支持格式和运行状态禁用。

## 5. 每次开发后的验证

### 自动检查入口

```bash
npm run check:config
npm run check:layout
npm run check
```

该命令依次运行前端构建、Rust 格式检查、`cargo check` 和单元测试。需要拆分排错时，再分别运行下面的命令。

### 前端

```bash
npm run build
```

检查：

- TypeScript 和 Vue 模板无错误。
- 生产构建没有引用开发服务器资源。
- 深色/浅色主题均可阅读。
- 980px 最小窗口下无关键控件重叠。

### Rust

```bash
cargo fmt --manifest-path src-tauri/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml
```

检查：

- 所有格式分支可编译。
- 并发为 1 和 8 时均能工作。
- 取消排队任务和运行任务均能正确结束。
- 错误信息不会泄漏密码。

### 手工归档矩阵

至少准备以下夹具：

1. 普通 ZIP，包含 3 层目录。
2. 有单根目录的 ZIP。
3. 根目录同时包含文件和文件夹的 ZIP。
4. 多个展平后同名文件的 ZIP。
5. 含 `../` 或绝对路径的恶意 ZIP/TAR。
6. 加密 ZIP、加密 7Z、错误密码。
7. TAR.GZ、TAR.BZ2、TAR.XZ。
8. 单文件 GZ/BZ2/XZ。
9. 正常 RAR、损坏 RAR、未安装外部工具。
10. 大文件与多个通道混合并发。

## 6. 发布前流程

1. 更新版本号：`package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`。
2. 更新 README 的格式支持和限制。
3. 运行完整验证矩阵。
4. 在 Windows、macOS、Linux 分别执行 `npm run tauri build`。
5. 对安装包签名并验证升级/卸载。
6. 检查第三方依赖许可证和安全公告。
7. 保留构建日志、测试结果和校验和。

## 7. 输出层级专项检查

每次修改层级逻辑后，至少验证保留结构、展平 0/1/2 层、跳过单一外层、输出容器开关、同名根目录去重和重名直接替换。界面示例路径与 Rust 实际落地结果必须一致。

## 8. 任务中心与安全删除专项检查

1. 成功任务必须生成 manifest；写入失败时界面应明确说明无法一键删除。
2. manifest 只能存放在应用数据目录，后端拒绝任意外部 manifest 路径。
3. 删除只允许访问输出根目录内的路径，并检查父目录符号链接。
4. 默认不得删除曾覆盖旧内容的文件。
5. 通道、文件和任务中心发起删除后，三个界面的状态必须同步。
6. 应用异常退出后，`queued` / `processing` 历史恢复为 `interrupted`，不得假装成功。
7. 同一目标目录并发任务必须串行落地；不同目标目录仍受全局并发数控制。

## 9. 外部命令与用户脚本专项检查

1. 用户提供的 BAT 作为二进制资源保存，不应通过文本读写悄悄改换 BOM 或换行。
2. 每次发布核对 BAT SHA-256。
3. `--dangerously-skip-permissions` 必须有明显风险说明，默认启用启动前确认。
4. 命令工作目录必须使用用户明确选择或通道明确计算出的目录。
5. 不在日志中保存密码、令牌或完整环境变量。
6. 仅在支持的平台启用对应命令，其他平台返回清晰错误。
