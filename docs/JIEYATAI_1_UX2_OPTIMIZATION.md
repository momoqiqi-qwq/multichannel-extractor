# jieyatai-1 UX2 优化说明

## 本轮已实现

- 总设置中的工作区显示项统一使用“开关”命名。
- 工作区显示开关从原有 8 项扩展到 16 项，新增：全部展开、全部开始、扫描收件、清理/重试、新建通道、通道排序、通道复制、通道删除。
- 新增“空队列开始时扫描最新版”开关，默认开启：通道没有待处理压缩包时，点击开始会扫描已配置的关键词收件目录，强制加入当前最新版并自动开始。
- 顶部“全部开始”同样支持空队列自动扫描；关闭该开关后，不会因为没有文件而偷偷扫描。
- 已完成通道的“扫描最新版并开始”属于显式操作，即使关闭自动扫描开关仍可手动使用。
- 通道卡片底部的已保存预设可直接删除；删除前确认，删除后有 Toast 与日志反馈。
- 设置搜索加入 `kg = 开关`，新增开关与空队列扫描设置均可搜索直达；上一版 `qd = 启动` 保留。
- 将开始流程从 `channels.ts` 拆到 `channelStartActions.ts`，避免主 store 继续膨胀，并统一单通道/全部开始的扫描逻辑。

## UX 细节

- “全部显示 / 精简显示”改为“全部打开 / 精简开关”，减少按钮与开关概念混用。
- 精简方案保留主开始、新建、删除、搜索和筛选，避免隐藏关键操作后难以恢复。
- 隐藏“全部开始”或“新建通道”后，Ctrl/Cmd+Enter 与 Ctrl/Cmd+N 仍可使用。
- 自动扫描关闭时，空队列开始会给出明确原因和设置路径，不会表现成无响应。

## 代码结构检查后的建议（未擅自大改）

1. `src/stores/channels.ts` 仍约 1196 行。建议下一步继续拆出“任务事件/恢复编排”，目标降到 800 行以内。
2. `AppearanceSettings.vue` 约 452 行。建议把“工作区开关”拆成独立组件，并用配置数组生成开关，避免界面与搜索索引不同步。
3. 项目中约有 16 处 `window.confirm`。建议改成统一的应用内确认对话框，视觉一致，也能支持“本次不再提示”等高级 UX。
4. 配置架构版本 `9` 仍在类型、状态和导出逻辑中重复出现。建议统一引用 `CONFIG_SCHEMA_VERSION`，减少升级时漏改。
5. 设置搜索索引目前需要手工维护。建议后续让设置组件和搜索元数据共享一份配置，新增开关时自动进入搜索。

这些属于结构性改动，当前版本没有全部实施，避免一次改动范围过大。
