# 解压台 0.6.1 优化报告

## 已执行的优化

### 1. 阻止启动命令行窗口

`src-tauri/src/main.rs` 增加 Windows GUI 子系统属性。相比“先创建再隐藏窗口”，这种方式不会分配额外控制台窗口，资源占用更低，也不会出现闪烁。

### 2. 个性化能力

新增字体和背景配置字段，并在设置页提供完整控制。背景图片会先复制到应用专用数据目录，再使用 Tauri `convertFileSrc` 加载；资产协议只开放应用数据目录范围，避免把用户任意文件路径暴露给 WebView。

### 3. 持久化写入合并

原实现对深层响应式状态的每次变化立即执行 JSON 序列化和 localStorage 写入。现在使用 180ms 防抖合并，同时在窗口关闭前执行最终刷新。

### 4. 目标目录锁缓存释放

原 `HashMap<String, Arc<Semaphore>>` 会永久保存每个出现过的输出目录。改为 `HashMap<String, Weak<Semaphore>>` 后，最后一个任务释放强引用时信号量可回收，并在后续请求时清理失效条目。

### 5. 代码职责收敛

外观设置的 DOM 属性、CSS 变量、本地图片 URL 和字体栈生成移入独立 `appearance` 服务。`channels.ts` 仅负责监听设置变化并调用服务，降低状态编排文件的界面耦合。

## 本轮未做、建议先征求意见的优化

### A. 继续拆分 `channels.ts`

仍可拆为工作区 CRUD、文件导入和任务运行时三个模块。改动面较大，建议在新增功能前完成，而不是和功能版本混在一起。

### B. 任务历史迁移到 SQLite

当前任务历史仍使用 localStorage。数量较大时，同步序列化会成为主要瓶颈。SQLite 能提供分页、索引和更可靠的历史数据管理，但需要引入数据库插件和迁移流程。

### C. 设置页搜索

设置项已经较多，后续可增加关键词搜索、最近修改和恢复单项默认值。这会明显改善查找效率，但需要给各设置项增加统一元数据。

### D. 窗口状态记忆

可记住窗口大小、位置和最大化状态。建议使用官方窗口状态插件实现，避免自行维护跨屏幕坐标兼容逻辑。

### E. 目标路径范围锁

当前锁只处理完全相同的最终目录。父目录和子目录同时写入仍可能冲突。下一版可实现祖先/后代路径冲突检测。

## 推荐下一版本

建议 0.7.0 聚焦“可发布验证与数据可靠性”：

1. Windows CI 自动构建 EXE、NSIS 和 MSI。
2. 任务历史迁移到 SQLite，并提供分页、筛选和清理策略。
3. 目标路径范围锁。
4. 解压前归档结构预览和预计输出路径检查。
5. 设置搜索与窗口状态记忆。
