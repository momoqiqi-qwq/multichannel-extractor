# 0.8.4 启动流程 UX 补丁

## 本次目标

1. 新安装与新通道默认开启“导入后自动开始”。
2. 通道没有待处理文件时，直接点击主开始按钮即可扫描关键词收件目录，选择当前最新版并立即开始。
3. 顶部“全部开始”在没有待处理文件时，会自动扫描可用关键词通道并开始。
4. 避免“扫描导入自动开始”和“点击开始”两条链路重复提交同一任务。

## 体验优化

- 空队列主按钮显示“扫描最新版并开始”，减少用户先理解“扫描收件”的步骤。
- 已完成通道如果配置了关键词收件，主操作改为“扫描最新版”，方便下一次更新。
- 扫描进行中按钮显示“扫描中…”并禁止重复点击。
- 空队列文案明确提示可以直接通过主按钮扫描最新版。
- 扫描结果中的“已选最新版 / 推荐最新版”按文件是否真的已经进入队列判断。
- 顶部开始按钮和 Ctrl/Cmd+Enter 均支持空队列自动扫描。
- 原有用户已经手动关闭的通道自动开始设置不会被强制覆盖；默认值只影响新安装、新通道和恢复默认。

## 建议的下一版本：0.9.0

优先做“持续收件自动化”，而不是继续增加零散按钮：

1. **下载目录实时监听**：文件下载完成且大小稳定后自动识别，不需要手动点扫描。
2. **真正的新版本判断**：记录上次成功版本，只在发现更高版本时启动；相同版本不重复解压。
3. **自动化规则页**：把关键词、排除词、平台、架构、预发布、版本策略合并成可测试的规则。
4. **自动化运行记录**：清楚展示“为什么选了这个文件、为什么启动/跳过”。
5. **通知降噪**：连续自动任务合并通知，只在失败、版本变化或需要用户处理时打扰。

这会把产品从“批量解压工具”推进到“下载产物自动处理工作台”。
